## Instruksi

### Langkah 1: Loading States
- Spinner/skeleton saat fetch data (dashboard load, login/register submit)
- Tombol disabled + spinner saat submit form (prevent double-click)
- Misal: `<LoadingSpinner />` component reusable

### Langkah 2: Error States
- API error → tampilkan pesan yang manusiawi, bukan JSON mentah
- Network error (backend mati) → "Tidak bisa terhubung ke server. Coba lagi nanti."
- Auth error (token expired) → auto-logout + redirect ke login
- Form validation error → inline error di bawah field

### Langkah 3: Empty States
- Dashboard tanpa habit → pesan ramah:
  - "Belum ada habit. Yuk tambah yang pertama! 🚀"
  - Tombol "Tambah Habit" yang prominent
- Tidak ada entry di stats → "Belum ada aktivitas tercatat."

### Langkah 4: Toast/Notification
- Sukses add/edit/delete habit → toast "Habit berhasil ditambahkan!"
- Sukses mark done → toast "Streak hari ini tercatat! 🔥"
- Error → toast merah dengan pesan error
- Bisa pakai library ringan atau custom component

### Langkah 5: Premium UI Polish & Pre-Flight Check
- Verifikasi dan jalankan Pre-Flight Check dari `design-guidelines.md`:
  - **Zero em-dashes:** Pastikan tidak ada karakter em-dash (`—`) di seluruh antarmuka.
  - **Color & Shape Consistency:** Sudut lengkung (border-radius) konsisten di semua komponen. Warna abu-abu netral terpadu (tidak mencampur cool & warm gray).
  - **Contrast Check:** Semua teks input, placeholder, tombol CTA lolos uji kontras WCAG AA (min 4.5:1).
  - **CTA Button Wrap Ban:** Tombol utama tidak berlipat menjadi 2 baris pada desktop.
  - **No Duplicate CTA Intent:** Satu label aksi per intent di seluruh halaman.
  - **Viewport Stability:** Gunakan `min-h-[100dvh]` untuk kestabilan tinggi viewport di mobile.

### Langkah 6: Final Testing & Audit
- Test flow lengkap secara interaktif: register → login → add habit → mark done → relapse → edit → delete → logout.
- Audit visual states lengkap: Skeleton loading, Empty dashboard, Error validation, dan Toasts.
- Jalankan di browser desktop dan simulasi mobile width untuk memeriksa responsivitas dan responsivitas interaksi (tactile feedback).
