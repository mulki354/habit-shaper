## Instruksi

### Langkah 1: Add Habit Modal/Form
Buat `frontend/src/components/AddHabitModal.tsx` (diimplementasikan sebagai `HabitModal.tsx` untuk menyatukan logika Add & Edit):
- Form fields: Nama habit (text input), Tipe (select/radio: BUILD atau BREAK)
- Submit → `POST /habits`
- Sukses → tutup modal, refresh list habits
- Error → tampilkan pesan

### Langkah 2: Edit Habit
- Tombol edit (ikon pensil) di setiap HabitCard
- Buka modal edit — pre-fill nama, tipe ditampilkan tapi TIDAK bisa diubah (disabled/readonly)
- Submit → `PATCH /habits/:id`
- Sukses → refresh list

### Langkah 3: Delete Habit
- Tombol delete (ikon trash) di setiap HabitCard
- Konfirmasi: "Yakin ingin menghapus habit '[nama]'? Semua data streak akan hilang."
- Confirm → `DELETE /habits/:id`
- Sukses → refresh list

### Langkah 4: Wiring ke Dashboard
- Tombol "Tambah Habit Baru" di dashboard → buka AddHabitModal
- Setelah add/edit/delete → refetch `GET /habits` (atau optimistic update)

## Bukti Verifikasi

Pengujian dilakukan menggunakan browser subagent setelah docker compose berjalan:
1. **Tambah Kebiasaan (Add Goal)**: Sukses membuat habit bertipe `BUILD` ("Olahraga Pagi") dan bertipe `BREAK` ("Begadang Malam"). Keduanya langsung ter-render di grid layout dashboard secara responsif.
2. **Ubah Kebiasaan (Edit Goal)**: Mengklik ikon pensil pada kartu "Olahraga Pagi" sukses memunculkan modal dengan isi terisi (pre-filled). Mengubah namanya menjadi "Olahraga Rutin" berhasil disimpan ke database. Input pilihan tipe kebiasaan (`BUILD`/`BREAK`) terkunci secara visual (disabled/readonly).
3. **Hapus Kebiasaan (Delete Goal)**: Mengklik ikon tempat sampah pada kartu "Begadang Malam" berhasil membuka dialog konfirmasi. Menyetujui dialog ("Ya, Hapus") memicu penghapusan data secara dinamis dari database, dan kartu tersebut langsung menghilang dari dashboard.
